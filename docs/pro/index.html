Security design

Built so the public demo has very little to attack.

Zero client secretsSecret API keys will only exist on a future server-side backend.
Hosted checkoutPayments will use Stripe-hosted checkout so card data never touches RevenuePilot.
Account isolationPaid accounts will use server-verified sessions and per-user access controls.
Rate limitsThe production API will enforce usage limits before costly AI calls.

No internet-facing system can truthfully be guaranteed “unhackable.” The goal is to reduce attack surface, keep secrets server-side, use trusted payment/auth providers, apply least-privilege access, and monitor abuse.
